# AntonCopilot

Личный Telegram Business Bot. Подключается к аккаунту Владельца, на каждое Входящее сообщение готовит через LLM Черновик ответа в стиле Владельца и отправляет его от имени Владельца — только после Одобрения.

```
Собеседник пишет Владельцу
        │  Telegram Business Connection
        ▼
   бот сохраняет сообщение ──► LLM (OpenRouter) + style.md
        │
        ▼
Черновик приходит Владельцу в чат с ботом  [Отправить]
        │  Владелец нажал
        ▼
ответ уходит Собеседнику от имени Владельца
```

Термины (Владелец, Собеседник, Черновик, Одобрение) — в [`CONTEXT.md`](CONTEXT.md), продуктовые правила — в [`PRD.md`](PRD.md).

## Стек

Python 3.12, aiogram 3 (polling, Business Connection), OpenRouter через httpx, PostgreSQL + SQLAlchemy 2 (async), Docker Compose на VPS. Почему VPS, а не serverless — [ADR 0001](docs/adr/0001-vps-not-serverless.md).

## Что уже работает

- Входящий текст и подпись к фото → Черновик Владельцу с кнопкой **Отправить**.
- **Отправить** доставляет ответ Собеседнику от имени Владельца; повторное нажатие ничего не отправляет.
- Кнопку может нажать только Владелец.
- Голосовые, документы и собственные сообщения Владельца Черновик не вызывают.
- Черновик пишется по последним 20 сообщениям чата: реплики Собеседника, Владельца и отправленные ответы, вложения — метками вроде `[голосовое]`. Старые сообщения удаляются.

Дальше по [`PRD.md`](PRD.md): 60 секунд тишины перед Черновиком, кнопки **Изменить / Отклонить**, Примеры ответа из правок Владельца, протухание Черновика через 24 часа, повтор при ошибке LLM.

## Запуск

```sh
cp .env.example .env   # заполнить BOT_TOKEN и OPENROUTER_API_KEY
docker compose up -d
```

Бота нужно подключить в Telegram: **Настройки → Telegram для бизнеса → Чат-боты**.

## Разработка

```sh
uv sync
docker compose up -d db   # PostgreSQL для тестов на 127.0.0.1:5433
make check                # ruff + mypy --strict + pytest
```

Тесты гоняют обработчики aiogram против настоящей PostgreSQL, а Telegram Bot API и OpenRouter подменены фейками.

Выкатка на VPS: `make deploy` (rsync + `docker compose up -d` на хосте `n3-vps`).
